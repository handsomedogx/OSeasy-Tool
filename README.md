# OeWinFix2

教学系统（Os-Easy 多媒体网络教室）学生端的三件事，只做这三件：

1. **全屏广播窗口 → 窗口化**（有标题栏、能拖动缩放、不再置顶铺满屏）
2. **保证键盘鼠标正常使用**
   * 主手段 **B：把* 全屏广播改写成窗口广播（不动客户端任何文件）
   * 键盘：周期性下发驱动级释放 IOCTL
   * 鼠标：**直驱光标**中继（探测驱动，只在证明客户端在吞事件时才接管）
3. **附带：镜像窗口** —— 你留在自己的桌面上，也能看到老师的广播画面

> 这是 OeWinFix（v1）的重写版。v1 里那些自造需求（改客户端内存、结束/挂起学生端、MMPC 服务控制、
> 十来个诊断开关、两层 CLI 解析）全部删掉了。所有机制都来自实测结论，见
> [`src/facts.h`](src/facts.h) 与 [`docs/evidence.md`](docs/evidence.md)。

## 怎么运行

```
双击 bin\OeWinFix2.exe        -> 托盘守护（需要管理员，清单里已声明 requireAdministrator）
```

托盘图标：

* 双击 = **打开状态面板**（见下）
* 右键 = 显示状态面板 / 窗口复位（摆成 80% 居中） / 看大画面（铺满↔还原） / 显示隐藏镜像窗口 /
  **鼠标中继（自动：探测到被吞才接管）** / **鼠标加速曲线（关 = 线性）** / 全屏广播改写 / 打开日志 / 退出

热键：`Ctrl+Alt+F9` 窗口复位、`Ctrl+Alt+F10` 紧急解封、**`Ctrl+Alt+F8` 看大画面（广播窗口铺满 ↔ 还原）**。三个都是 `RegisterHotKey` 注册的系统级热键（`MOD_NOREPEAT`，长按不连发）。

## 状态面板

![状态面板](docs/status-panel.png)

双击托盘图标（或右键"显示状态面板"）打开，**启动时也会自动弹一次**。它**有任务栏按钮**、也在 Alt+Tab 里 ——
早年用 `WS_EX_TOOLWINDOW` 把它做成了"工具窗口"（无任务栏、无 Alt+Tab），结果托盘图标一被 Windows
收进"隐藏的图标"，就彻底找不到界面了。500ms 自己刷新，纯 Win32 子控件，没有 .rc、没有额外依赖。

* 四段状态：桌面 / 广播 / 鼠标 / 键盘，加一行热键提示
* 按钮：**窗口复位（F9）**、**看大画面（F8）**、打开日志、**退出程序**；镜像窗口只在 B 方案失效时出现
* 底排开关：鼠标中继（自动）、加速曲线、灵敏度（改完点"应用"，写入 HKCU 下次生效）
* `WM_CLOSE` 只认前台来源 —— 广播期间客户端会给不相关窗口群发 `WM_CLOSE`（实测能刷到 0.5 秒一次），
  面板不会被它关掉；你自己点 X 时窗口一定已激活，所以也不误伤

### 找不到托盘图标 / 双击 exe 只有一个弹窗？

* 程序是**单实例**的：已经在跑的时候再双击，会**把已有实例的面板叫出来**
  （`PostMessage` 请对方弹面板，然后用"面板窗口是否真的出现"来确认；对端是旧版本不响应时才退回弹框）。
  早期版本用的是命名事件 ACK，实测偶发收不到 -> 已改成观察窗口状态。
* 启动时会自动弹面板；托盘图标另有气泡提示"图标在通知区（可能收在'隐藏的图标'里）"。
* 资源管理器重启后通知区会被重建，程序收到 `TaskbarCreated` 会**自己把图标补回去**。
* **完全不用托盘也能操作**：`OeWinFix2.exe --panel` 弹面板，`OeWinFix2.exe --quit` 正常退出，
  面板右下角也有"退出程序"。



命令行（需要看诊断时）：

```bat
OeWinFix2.exe --status            :: 打印状态后退出
OeWinFix2.exe --windowize-now     :: 立刻窗口化一次后退出
OeWinFix2.exe --quit              :: 让已在运行的实例正常退出（不用找托盘图标）
OeWinFix2.exe --panel             :: 让已在运行的实例把状态面板弹出来
OeWinFix2.exe --no-panel          :: 启动时不弹面板（默认会弹）
OeWinFix2.exe --once              :: 各线程跑一轮自检（脚本里用）
OeWinFix2.exe --no-relay --no-mirror :: 只要窗口化 + 键盘 + 桌面
OeWinFix2.exe --accel on          :: 鼠标加速曲线打开（默认关 = 线性、灵敏度低）
OeWinFix2.exe --sens 1.5          :: 鼠标灵敏度倍数（默认 1.0）
OeWinFix2.exe --relay-force       :: 不等探测，直接接管鼠标中继（测试用）
OeWinFix2.exe --help              :: 全部开关
```

## 原理（四件事）

| 层 | 现象 | 本程序的对策 | 实测依据 |
|---|---|---|---|
| **输入归属** | 广播时客户端把**输入桌面**切到 `NetTeachingDesktop`，你自己的桌面收不到任何鼠标键盘输入 | 250ms 检测，发现不是自己的桌面就 `SwitchDesktop` 夺回 | 旧项目日志 299 次采样 `inputDesktop=NetTeachingDesktop` |
| **鼠标被吞** | 客户端装 `WH_MOUSE_LL`，只放行 `dwExtraInfo==0x12452`，其余真实鼠标事件 `return 1` 吞掉 | 自己的钩子抢先丢弃原件 + 从 **Raw Input** 取设备原始增量 + **`SetCursorPos` 直驱光标** | 广播中注入 `extraInfo=0` 位移 0、`0x12452` 位移 97,60；直驱后零延迟（2026-10-20） |
| **键盘被锁** | `KbFilter.sys` 驱动级封锁 | 每 400ms 向 `\\.\OeKbdFilter` 下发释放 IOCTL `0x000B2008` | 旧项目实测 `sent OK` 后键盘立即恢复 |
| **画面** | 夺回桌面后，广播窗口在别的桌面上，看不见了 | 镜像窗口：`PrintWindow(PW_RENDERFULLCONTENT)` 抓那个窗口，等比缩放显示 | 窗口所在桌面非活动时仍能抓到 98% 非黑内容（[截图](docs/mirror-live.png)）；动图窗口两帧间 99.96% 采样变化 |

### 五条"别踩"的经验（都写进注释了）

* **不要改客户端内存**：主客户端 `Student.exe` 被 `ProcFireWall` 驱动保护，`OpenProcess` 返回 5，连它的模块表都读不到。
* **鼠标位移不要用 `SendInput` 逐事件重放**（2026-10-20 实测）：补出来的事件必须**穿过客户端的低级钩子**才生效，钩子链是串行的；125Hz+ 鼠标时发送速度超过链条消化速度，事件就在输入队列里积压 —— 总位移没错但被匀速排空，观感是"实际移了一大段、指针在后面慢慢追上来"（像远程桌面）。
  同一段操作：旧法 5 秒往链上塞 **975** 个事件；`SetCursorPos` 直驱只有 **4** 个（全是别人发的）。
* **不要逐事件复刻绝对坐标**：事件被吞时坐标**不累积**（实测 6 步只走 22px，白名单对照 165px）。
* **只信物理设备的 Raw Input**：`hDevice == NULL` 的是注入输入（**包括我们自己注入的**）。不过滤就会形成反馈环，把指针顶死在屏幕角落。
* **锁边要连虚拟位置一起夹**：撞到屏幕边缘时不夹住内部坐标，回头会先"还债"，表现为反向不动一下。

## 鼠标：直驱光标 + 加速开关（2026-10-20 重写）

**探测驱动**：每 5 秒做一次差分探测 —— 普通注入 3px 动不了、`0x12452` 注入 3px 能动，才判定"客户端在吞事件"，
此时才装钩子并接管。客户端没吞的时候完全透明（零钩子、零注入、零延迟）。

**接管时**：钩子线程只做 `return 1`（不睡、不写盘、不探测、不注入）——
低级钩子是同步的，装钩线程一阻塞，**全系统鼠标跟着停**，这是旧版"卡"的根因。
位移从 Raw Input 取设备增量，用 `SetCursorPos` 直接设绝对坐标：不进钩子链、不排队，
一次调用立即到位。按键仍然走 `SendInput`（必须作为真实输入事件送达窗口），带 `0x12452` 标记。

**加速曲线（开关，默认关）**：
系统"提高指针精确度"会按速度放大位移（本机阈值 `6/10` → x2/x4）。直驱绕过了它，于是自己复刻：
把移动量按 dt 归一成"每 10ms 的计数"当速度，再比阈值。归一很关键 ——
不除以 dt 的话慢速也会被判成高速（实测 `x4` 命中 264/277，指针会飞）。

* 默认 **关** = 线性 1:1，灵敏度低但完全可预测（用户偏好）
* 开关：托盘右键"鼠标加速曲线"、或 `--accel on|off`
* 选择存在 `HKCU\Software\OeWinFix2\MouseAccel`，重启保留

**安全阀**（任一触发都不会让鼠标变死）：
只有"raw 通路就绪"且"正在接管"才丢原件；输入桌面不是自己就停手；
连续设置光标失败 30 次就停手；广播窗口消失后自动停止接管并卸钩子。

## 看大画面（F8）—— 为什么不切桌面

B 方案把"全屏广播"改写成"你桌面上的一个窗口"，所以**教学桌面上已经没有广播窗口了**。
这时按 F8 切过去只会看到空桌面 —— 不是按钮坏了，是那儿真的没东西（实测：`EnumDesktopWindows`
在 `NetTeachingDesktop` 上找不到 `MultiRenderWindowClass`）。

所以 F8 换成这件事：**把广播窗口在工作区内铺满 / 还原**。

* 铺满：覆盖整个工作区（不盖任务栏），带 `SWP_NOSENDCHANGING`，否则客户端会在
  `WM_WINDOWPOSCHANGING` 里把尺寸顶回去（实测）
* 还原：回到按 F8 之前的位置尺寸；之前没有有效矩形时用"工作区 80% 居中"
* 不切桌面 -> 面板、任务栏、其它窗口全都在原位；鼠标键盘也不用跨桌面

只有在 B 方案失效（广播窗口真的占着教学桌面）时，同一个按钮 / F8 才会变回"切到课堂桌面"，
并且切过去之后**暂停 60 秒自动夺回**（`DesktopHoldReclaim`）—— 否则 250ms 就被拉回来，看起来像没反应。

## 构建

```bat
build.bat                       :: 需要 VS2022 的 vcvarsall.bat（脚本里 VCVARS 可改）
                                ::   bin\OeWinFix2.exe            主程序（唯一要用的）
                                ::   bin\dev\FakeBox.exe          回归测试替身
                                ::   bin\dev\relaytest.exe        中继自检
                                ::   bin\dev\uitest.exe           只画面板，验收界面用
                                ::   中间产物全在 bin\obj\（可随手删）
build.bat OeWinFix2.new.exe     :: 主程序正在运行时，先编到别名，之后再换（见 swap.bat）
```

静态 CRT、x86、只依赖系统 DLL，拷一个 exe 就能用。

### bin\ 里只该有两个 exe

| 文件 | 是什么 |
|---|---|
| `bin\OeWinFix2.exe` | **就是程序**，双击它 |
| `bin\OeWinFix2.prev.exe` | 上次换装前的备份，**只在回滚时用**（换装时由 swap.bat 生成） |

其余都在 `bin\dev\`（测试工具，平时不用）和 `bin\obj\`（编译中间物，可以整个删掉）。
开发时的临时命名（`*.new.exe` / `*.pending.exe` 之类）到换装完成就不需要了，删掉即可。

**换装（主程序正在跑、不能被杀时）**：

```bat
build.bat OeWinFix2.new.exe     :: 1) 编到别名
swap.bat                        :: 2) 退出托盘程序后运行它：备份旧 exe -> 换新 -> 启动
```

`swap.bat` **不会**替你结束正在跑的守护进程；它检查到在跑就只打印提示。

## 验证（可重复，别在有课的时候跑 —— 它会结束进程、接管鼠标）

```powershell
powershell -ExecutionPolicy Bypass -File test\check.ps1
```

`bin\dev\FakeBox.exe` 会加载**真实的 `StudentLogic.dll`**、用它自己的钩子过程（RVA `0x80190`）装
`WH_MOUSE_LL`，再建一个同名窗口类的全屏置顶窗口 —— "鼠标锁"这一层跑的是客户端原件，不是仿写。

断言清单：

```
A0 fake broadcast window exists
A1 plain event swallowed by client hook (moved=0)
A2 whitelisted 0x12452 passes (moved>0)
B1..B4 windowize: TOPMOST/POPUP 清除、补标题栏、不再是全屏尺寸
C1 relay 接管中 0x12452 依然放行（回归：曾经连白名单都被冻住）
D1 relay 状态 -> 接管中（探测到客户端在吞事件）
D2 注入包被忽略（hDevice 过滤，无反馈环）
D3 keyboard release IOCTL OK
```

（脚本里注入的都是"注入输入"，所以 `位移` 计数在自动化里是 0 —— 位移只有在**真的用手移动鼠标**时才会增长，
这条用 `bin\dev\relaytest.exe` 或直接看状态面板验证。）

另外有一个独立的中继自检，不需要 FakeBox、也不动主程序：

```bat
bin\dev\relaytest.exe        :: 装钩子 -> 探测 -> 接管 -> 打印 8 秒统计 -> 卸载并干净退出
```

## 有意不做的事

* 不结束、不挂起学生端进程，不动 `MMPC` 服务，不碰 `ProcFireWall`/`FbdATS` 驱动；
* 不做内存补丁（见上：主客户端打不进去）；
* 不改客户端任何文件，不做登录自启计划任务（需要就说，功能很小但没必要默认塞进来）；
* **不做"切到教学桌面看广播"**：B 方案生效时那个桌面是空的；看大画面用 F8 让窗口铺满，
  跨桌面驱动光标/键盘那套只在 B 失效时才有意义；
* 不接管桌面锁定（`systemoper!SYS_LockScreen` 那条链路是另一回事）。

## B 方案：全屏广播 → 窗口广播

**思路（来自同类开源工具箱 OsEasy-ToolBox 的启发，但做法不同）**：不去对抗"广播进来以后"的锁，
而是**在客户端启动渲染器的那一刻把参数改掉**。

实测依据：

* 渲染器 `ScreenRender.exe` 的**命令行**里带着整条广播参数：
  `{#decoderName#:#h264#,#fullscreen#:1,#local#:#10.69.46.23#,#port#:7778,...}`
* 我们自己用这行参数拉起客户端的 `ScreenRender.exe`，能正常渲染老师画面（`docs/bcast-self-launch.png`）
  —— 不需要替换客户端的任何文件（那个工具箱是换成自己的替身，要动安装目录）。
* 全屏广播（`#fullscreen#:1`）才会带来"锁键鼠 + 切桌面"；窗口广播的会话里客户端不上锁。

**v2 的做法**（`src/bcast.cpp`）：

1. 每秒枚举 `ScreenRender.exe`，用 `NtQueryInformationProcess(ProcessCommandLineInformation)` 读命令行；
2. 只挑含 `#fullscreen#:1` 的实例 → `TerminateProcess` 结束它；
3. 用**同一条命令行**（只把 `:1` 换成 `:0`，等长替换不破坏引号）`CreateProcessW` 重新拉起；
4. 防抖：一分钟最多 8 次；只动全屏实例；自己拉起的 pid 绝不误杀。

**注意**：B 方案接管了"输入桌面"这一层，但**不会**让客户端卸掉它的鼠标钩子 ——
所以窗口化之后鼠标仍然可能是死的，需要上面的直驱中继。这两件事是分开的两层。
